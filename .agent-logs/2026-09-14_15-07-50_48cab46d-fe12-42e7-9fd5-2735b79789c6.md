**Rules the schema has to enforce:**
- **Balance never goes negative.** A charge is a conditional `UPDATE users … WHERE credit_balance >= cost`, done in the same transaction as the ledger insert and the job insert. If no row is updated, the paywall opens.
- **No double charge or double refund.** The unique `(job_id, reason)` key guarantees it, even when a poll and the background sweep run at the same moment.
- **Guarded state changes.** Each transition is an `UPDATE … WHERE status IN (allowed)`. Finished states (succeeded, failed, canceled) never change. Assets are inserted in the same transaction that marks a job succeeded.
- **Refunds:** failed and canceled jobs are refunded in full; succeeded jobs are not.

**Deliberately *not* tables:**
- **Explore sections:** editorial content, never written to by users, so a typed config file.
- **Sample-media pool** used by the simulated provider: a manifest file.
- **Sessions:** a signed cookie holding the user id.
- **Subscriptions:** a plan is a field on the user, and changing plan is a ledger grant. Billing periods only matter with real payments, which are cut.
