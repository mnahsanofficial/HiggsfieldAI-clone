## 2. Data model

Money-like values are stored as **integer tenths of a credit**. The image price is 6.5, so floats would eventually drift the ledger.

```text
plans            id ('free'|'basic'|'pro'|'max'), name, tagline, rank, monthly_credits,
                 price_monthly_cents, price_annual_cents, outcome_copy jsonb
users            id uuid, kind ('guest'|'registered'), display_name, avatar_url,
                 plan_id → plans, credit_balance int (tenths, cached), created_at
credit_ledger    id, user_id, delta int (tenths, ±), balance_after int,
                 reason ('signup_grant'|'plan_grant'|'demo_topup'|'generation_charge'
                         |'generation_refund'|'adjustment'),
                 job_id → generation_jobs null, created_at
                 UNIQUE (job_id, reason)      -- one charge and at most one refund per job
models           id ('seedance_2_5'), name, vertical ('image'|'video'), badge ('top'|'new'|null),
                 description, provider_key, provider_model_ref, min_plan_rank,
                 capabilities jsonb (aspects, resolutions, durations, qualities, max_batch,
                                     accepts_image_input),
                 pricing jsonb (base_tenths, multipliers per option), cover_media, sort, active
presets          id, slug, name, category ('camera'|'vfx'|'framing'|'general'), vertical,
                 description, preview_media (looping video), default_model_id → models,
                 compatible_model_ids text[], prompt_modifier, motion_params jsonb,
                 badge, sort, featured
generation_jobs  id uuid, user_id, vertical, model_id, preset_id null, prompt,
                 params jsonb (aspect, resolution, quality, duration_s, batch_size, seed),
                 input_asset_id → assets null, cost_tenths,
                 status ('queued'|'processing'|'succeeded'|'failed'|'canceled'), progress 0–100,
                 provider_key, provider_job_ref, provider_state jsonb,
                 error_code, error_message, retry_of_job_id → generation_jobs null,
                 cancel_requested_at, created_at, started_at, finished_at
assets           id uuid, user_id null, job_id null, kind ('image'|'video'),
                 source ('generated'|'seed'|'upload'), url, poster_url, width, height,
                 duration_ms, model_id, preset_id, prompt, is_public, created_at, deleted_at
```

**Rules the schema has to enforce:**
- **Balance never goes negative.** A charge is a conditional `UPDATE users … WHERE credit_balance >= cost`, done in the same transaction as the ledger insert and the job insert. If no row is updated, the paywall opens.
- **No double charge or double refund.** The unique `(job_id, reason)` key guarantees it, even when a poll and the background sweep run at the same moment.
- **Guarded state changes.** Each transition is an `UPDATE … WHERE status IN (allowed)`. Finished states (succeeded, failed, canceled) never change. Assets are inserted in the same transaction that marks a job succeeded.
- **Refunds:** failed and canceled jobs are refunded in full; succeeded jobs are not.

**Deliberately *not* tables:**
- **Explore sections:** editorial content, never written to by users, so a typed config file.
- **Sample-media pool** used by the simulated provider: a manifest file.
- **Sessions:** a signed cookie holding the user id.
- **Subscriptions:** a plan is a field on the user, and changing plan is a ledger grant. Billing periods only matter with real payments, which are cut.

**Pricing** is `base × resolution × quality × duration × batch`, rounded to 0.5 credits. The observed anchors:
